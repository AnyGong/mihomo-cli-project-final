# mihomo Kernel Pure CLI Manager Design Document – macOS (Apple Silicon)
### v2 — revised after design review

This tool is a dedicated pure command-line management utility for the mihomo kernel on macOS Apple Silicon devices. It has no graphical interface. All workflows including kernel version management, subscription configuration management, network proxy mode switching, rule mode switching, etc., are performed entirely via terminal commands. It is built for core scenarios such as local kernel execution, configuration updates, and version iteration.

> Changes from v1 are marked **[NEW]** or **[REVISED]**.

## 1 Configuration Module

### 1.1 Kernel Configuration Management

Storage Directory: `config/mihomo`

#### 1.1.1 List Display Rules

Default sorting priority for the list: Active > Last Used > Version > Added Time. Displayed fields are as follows:

- Status: Marked with ✅ for the currently active kernel; blank otherwise
- Version: Full semantic version string of the mihomo kernel
- Last Used: Timestamp when the kernel was last started; blank if never used
- Added Time: Timestamp when this kernel version was first downloaded and added locally

#### 1.1.2 Row Operations & Permission Constraints

Supports selecting any entry for deletion or version switch operations.

Hard restriction: The currently running kernel version cannot be deleted or switched. A clear error prompt is returned when attempting such operations.

#### 1.1.3 Version Sync Capabilities

- Stable Release Update Check: Automatically fetches the latest stable release from the official repository, displays the target version and official publish time, and interactively prompts the user to confirm download and update. If no newer version exists, the terminal outputs a message indicating the local version is already the latest stable build.
- Full Version List Download: Fetches the latest 10 releases from upstream (including stable, alpha, beta, pre-release builds). All version numbers are listed in the terminal, with the latest stable release highlighted by default. Versions already present locally are skipped. Newly downloaded binaries are named by version number and stored under the tool's working directory.
- **[NEW] Version pinning beyond the default window:** If the desired version is not among the latest 10 fetched releases, the user can supply an explicit version tag (e.g. `mihomo kernel fetch v1.18.2-alpha`) to fetch it directly from the upstream release API by tag, bypassing the top-10 list. The same official-repository provenance check (see 4.1.3) applies regardless of fetch path.

### 1.2 Subscription Configuration Management

Storage Directory: `config/subscriptions`

#### 1.2.1 List Display Rules

Default sorting priority for the list: Active > Last Used > Updated Time > Added Time. Displayed fields are as follows:

- Status: Marked with ✅ for the currently active subscription; blank otherwise
- Subscription Name: User-defined or auto-generated subscription label
- File Path: Filename only for files inside the default directory; absolute system path for files outside the default directory
- Last Used: Timestamp when this subscription was last activated; blank if never used
- Added Time: Timestamp when the subscription was first imported
- Updated Time: System file modification time for local subscriptions; timestamp of last online refresh for remote URL subscriptions
- Local: Marked with ✅ for local subscription files; blank otherwise
- Remote: Marked with ✅ for remote URL subscriptions; blank otherwise
- Refresh Behavior: **[REVISED]** Local subscriptions display `Watch-on-use` (re-read from disk at activation time, not on a timer); remote subscriptions display a numeric interval in minutes. This replaces the v1 `Always` label, which conflated timer-based polling with read-on-activation semantics.

#### 1.2.2 Row Operations & Validation Rules

Supports selecting any entry for deletion, configuration editing, or activation switch.

Pre-switch validation: Before activating a subscription, the tool automatically validates file format, rule validity and parameter syntax. If validation fails, specific error details are printed and the switch is aborted.

Permission restriction: The currently active subscription cannot be deleted, modified or hot-swapped.

**[NEW] Import safety:** The tool never mutates a user's original subscription file in place. Any mode/rule override generated by this tool (see 2.4) is stored as a separate overlay applied at runtime, so the source file on disk always matches what was imported.

#### 1.2.3 Add New Configuration

Supports two types of new configurations: local and remote. All imported configurations undergo unified format, rule and parameter validation; invalid configurations are rejected immediately.

Name generation rule: The filename at the end of the source path is used as the default name. If a configuration with the same name already exists at the same path, the user is prompted whether to overwrite. If overwrite is declined, a serial number is appended to the default name to avoid conflicts.

- Local Configuration: Required fields – local file path, subscription name
- Remote Configuration: Required fields – remote subscription URL, refresh interval (unit: minutes, default 60), subscription name

## 2 Core Function Module

Provides pure CLI one-click switching for network runtime mode and traffic rule mode without manual edits to config files.

### 2.1 Network Settings

Three mutually exclusive network modes; only one may be active at a time:

- System Proxy: Enable macOS global system proxy, hooks into the system network stack
- Tun Mode: Load virtual network interface to hijack all system traffic
- Proxy Mode: Enable custom port-based proxy forwarding

**[NEW] Interface targeting for System Proxy:** On activation, the tool enumerates active network services via `networksetup -listallnetworkservices`, applies the proxy to the service currently carrying default route traffic, and prints which interface was targeted. If multiple services are simultaneously active (e.g. Wi-Fi + USB Ethernet), the tool prompts the user to pick one rather than silently applying to all.

**[NEW] Conflicting proxy manager detection:** Before writing System Proxy settings, the tool checks whether a system proxy is already set by another process and, if so, warns the user and asks for explicit confirmation to overwrite rather than doing so silently.

### 2.2 Rule Modes

Three mutually exclusive traffic routing modes; only one may be active at a time:

- Rule Mode: Route traffic intelligently per the rule list inside the active subscription (default mode)
- Global Mode: Force all traffic through the proxy tunnel
- Direct Mode: Forward all traffic locally without passing through the mihomo kernel

### 2.3 macOS System Integration **[NEW]**

This subsection specifies the platform-level mechanics referenced elsewhere in the document but previously left implicit.

- **Privilege model:** Tun Mode and low-numbered port binding require elevated network capability. The installer applies the equivalent of `setcap`-style entitlement to the mihomo binary at install/update time (via a one-time authenticated `sudo` step), so day-to-day `tun on`/`tun off` commands do not require a password prompt per invocation.
- **Process supervision:** The "auto-restart on crash" and "process lock" behaviors in 4.1.2 are implemented as a per-user `launchd` agent (`KeepAlive` + `ThrottleInterval`), installed during first-run setup and controllable via `mihomo daemon install|remove|status`. The manager CLI itself remains a stateless client that talks to the running kernel over its local control API; it does not need to stay running in a foreground terminal for the kernel or Tun mode to persist.
- **Scope:** All `networksetup`, `launchd`, and privileged-binary operations are macOS/Apple Silicon-specific and are not abstracted behind a cross-platform layer in this version.

### 2.4 Mode & Subscription Rule Precedence **[NEW]**

Subscription YAML files may themselves declare a `mode` and proxy-groups. To keep the "no manual edits to config files" guarantee in section 2 while avoiding ambiguity about which setting wins:

- CLI-driven Rule Mode switches (2.2) are applied as a runtime overlay on top of the subscription's own `mode` field, using the mihomo control API, not by editing the subscription file.
- The overlay always takes precedence over the subscription's embedded `mode` value for the duration the subscription is active.
- On subscription activation, the tool prints the subscription's embedded default mode and the mode actually in effect if they differ, so the user is never surprised by a mismatch.

### 2.5 Teardown / Uninstall **[NEW]**

A `mihomo uninstall` command reverses all system-level state so the tool never leaves the Mac in a partially-proxied or orphaned state:

- Disables and removes the `launchd` agent installed per 2.3
- Reverts System Proxy settings via `networksetup` if currently applied by this tool
- Tears down the Tun virtual interface if active
- Optionally removes downloaded kernel binaries, subscriptions, and logs (separate `--purge-data` flag, off by default so config isn't deleted accidentally)

## 3 Global General Constraints

The running kernel and active subscription are locked and protected. Destructive modifications, deletions and hot-swaps are blocked to prevent unintended service interruption.

All create, modify and switch operations run pre-flight validity checks and return precise root-cause errors to improve operational robustness.

All status and timestamp fields refresh automatically to keep terminal display consistent with real runtime state.

All features target macOS Apple Silicon; command execution, file I/O and system permission calls are optimized for the ARM64 architecture.

**[NEW] Cross-invocation concurrency:** In addition to the single-instance lock on the mihomo kernel process itself (4.1.2), the manager CLI takes an advisory file lock around any config-mutating command (`kernel switch`, `sub switch`, `sub add`, `net`, `mode`). A second CLI invocation attempting a mutating command while one is in progress is rejected with a clear "operation already in progress" error rather than racing.

## 4 Stability & Security Guarantees

### 4.1 Runtime Stability Guarantees

#### 4.1.1 Atomic Configuration Changes & Automatic Rollback

Kernel switch, subscription switch and network mode switch follow an atomic workflow: `Pre-validation → Temp Write → Liveness Verification → Persist`. The current active configuration is automatically backed up before changes. If validation fails, kernel reload fails or network connectivity breaks during the operation, the tool rolls back immediately to the previous stable state to avoid partial config application or total network outage.

#### 4.1.2 Runtime Hardening & Process Supervision

Enforce the global lock rule: running kernel and active subscription are protected from deletion, modification and forced switching. All high-risk actions are guarded by pre-state checks to prevent accidental service outage at the entry point.

Built-in process health polling to monitor mihomo status. Auto-restart on unexpected crashes not triggered by user-initiated stop. A process lock prevents multiple instances from starting simultaneously, which would cause port conflicts and config corruption. **[REVISED]** This supervision is implemented via the `launchd` agent described in 2.3, not an in-process watchdog, so it survives terminal closure.

#### 4.1.3 Full-Link Pre-Flight Validation

Extends validation beyond basic subscription syntax checking into multi-layer guards:

- Kernel Layer: Every kernel binary is fetched exclusively over HTTPS directly from the official upstream mihomo GitHub releases API, matching the exact requested tag. No local SHA256 verification is performed against a separately-published checksum — the official repository, reached over TLS, is the trust boundary. A download that does not resolve to an official release asset (e.g. an unexpected redirect, a 404 on the expected tag, or a response that fails to parse as a valid release artifact) is refused.
- Config Layer: YAML syntax check, parameter validity check, rule semantic validation, port/path collision check. No change takes effect without passing validation.
- Network Layer: Pre-detect port occupancy and permission availability before enabling system proxy or Tun mode to intercept known conflicts early. **[REVISED]** Also detects a pre-existing system proxy owned by another application (see 2.1) before overwriting.

#### 4.1.4 Fault-Tolerant File I/O

All config, kernel and metadata files use the `temp-file-write + atomic-replace` pattern to avoid corruption if the program terminates mid-write. Remote subscription and kernel downloads support resume-on-retry and automatic retries on failure; network flakiness will not corrupt existing local files.

#### 4.1.5 Error Isolation & Graduated Logging

A single failed subscription refresh or abnormal version does not disrupt the global service; error domains are strictly isolated. All workflows produce leveled logs (`info`/`warning`/`error`) with timestamp, action, payload and error details for troubleshooting and audit. A single module failure will not crash the entire tool.

#### 4.1.6 Audit Log Retention **[NEW]**

Audit logs (below) and leveled operational logs are append-only but not unbounded: logs rotate by size (default 10 MB per file, 5 files retained) via a standard rotate-and-compress scheme. Rotation never deletes the current in-progress log file mid-write, preserving the append-only guarantee for any single session's log.

**Auditable Operation Trail**

All actions persist audit logs containing timestamp, action type, target object and execution result. Log files are append-only and tamper-resistant for postmortem investigation and traceability.

## 5 Architecture Design Principles

The tool is designed with **high cohesion, low coupling, scalability and maintainability** as the core architectural goals, guiding all module design, function iteration and code implementation work. It ensures that each functional module focuses on independent core responsibilities, minimizes mutual dependency between modules, reserves scalable interfaces for subsequent function expansion, and simplifies subsequent debugging, optimization and maintenance costs.

## 6 Command Surface **[NEW]**

Sketch of the CLI grammar, following a `mihomo <noun> <verb> [args]` structure consistent across modules. All mutating commands acquire the advisory lock from §3 and run the pre-flight validation from §4.1.3.

### 6.1 Kernel (`config/mihomo`)

| Command | Description |
|---|---|
| `mihomo kernel list` | List installed kernels per §1.1.1 sort/fields |
| `mihomo kernel check` | Check for newer stable release; prompt to download |
| `mihomo kernel fetch [--all \| <version>]` | Download latest 10 releases, or a specific version tag (§1.1.3) |
| `mihomo kernel use <version>` | Switch active kernel; blocked if `<version>` is currently running |
| `mihomo kernel rm <version>` | Delete a kernel binary; blocked if currently running |
| `mihomo kernel status` | Show currently running kernel, uptime, health |

### 6.2 Subscription (`config/subscriptions`)

| Command | Description |
|---|---|
| `mihomo sub list` | List subscriptions per §1.2.1 sort/fields |
| `mihomo sub add local <path> [--name <name>]` | Import a local subscription file |
| `mihomo sub add remote <url> [--interval <min>] [--name <name>]` | Import a remote subscription |
| `mihomo sub use <name>` | Activate a subscription; runs pre-switch validation (§1.2.2) |
| `mihomo sub edit <name>` | Open subscription in `$EDITOR`; blocked if active |
| `mihomo sub rm <name>` | Delete a subscription; blocked if active |
| `mihomo sub refresh <name>` | Force an out-of-cycle refresh for a remote subscription |
| `mihomo sub validate <name>` | Run format/rule/param validation without activating |

### 6.3 Network Mode (§2.1)

| Command | Description |
|---|---|
| `mihomo net status` | Show current network mode and target interface |
| `mihomo net system-proxy on\|off` | Toggle macOS system proxy (interface-targeting per §2.1) |
| `mihomo net tun on\|off` | Toggle Tun mode |
| `mihomo net proxy-mode on\|off [--port <port>]` | Toggle port-based proxy forwarding |

### 6.4 Rule Mode (§2.2, §2.4)

| Command | Description |
|---|---|
| `mihomo mode status` | Show active rule mode and the subscription's embedded default, flagged if they differ |
| `mihomo mode rule` | Switch to Rule Mode |
| `mihomo mode global` | Switch to Global Mode |
| `mihomo mode direct` | Switch to Direct Mode |

### 6.5 Daemon / Supervision (§2.3, §4.1.2)

| Command | Description |
|---|---|
| `mihomo daemon install` | Install the `launchd` agent for persistence and auto-restart |
| `mihomo daemon remove` | Remove the `launchd` agent |
| `mihomo daemon status` | Show supervision state, restart count, last crash reason |

### 6.6 Lifecycle & Diagnostics

| Command | Description |
|---|---|
| `mihomo start \| stop \| restart` | Manual kernel lifecycle control |
| `mihomo log [--level info\|warning\|error] [--follow]` | Tail leveled logs |
| `mihomo audit [--since <date>]` | Query the audit trail |
| `mihomo doctor` | Run all pre-flight checks (kernel hash, port availability, proxy conflicts) without applying changes |
| `mihomo uninstall [--purge-data]` | Full teardown per §2.5 |
